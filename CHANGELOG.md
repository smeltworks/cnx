# Changelog

All notable changes to cnx will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- **The library reports a cnx symbol's language as `"cnx"`** (Issue #2173). `TLanguage`, the
  type of `ISymbolInfo.language`, is `"cnx" | "c" | "cpp"`. Code that compares `language` with
  the cnx value must compare it with `"cnx"`.
- **The Prettier plugin is `@smeltworks/prettier-plugin-cnx` and its parser is `cnx`** (Issue
  #2182). A Prettier config names `parser: "cnx"`.
- **`CNX_CROSS_COMPILER` names the compiler a project reads its headers with** (Issue #2166).
  No other variable is read. Set it in build scripts and CI.
- **Generated files say `generated by cnx`** (Issue #2168). The banner every generated `.c`,
  `.cpp`, `.h` and `.hpp` file opens with is now ` * generated by cnx from: <file>` (or
  ` * generated by cnx` with no source), and the interrupt-mask fallback reads
  `#error "cnx: …"`. Tooling that matches the banner must match `generated by cnx`. Header
  discovery recognizes only this banner (#2183), so a header an earlier release generated reads
  as a hand-written C header: delete generated headers before the first run with this release,
  and let it write them again.
- **A generated quoted `#include` is spelled from the file that carries it** (ADR-010, Issues
  #2272, #1473, #1746). A file's output no longer depends on which entry pulled it in, and it
  compiles with no `-I` where `cnx` wrote it. A header in a subdirectory names its sibling as
  `"bitmaps.h"`, not `"lib/bitmaps.h"`, and a `.c` names its own header as `"uart.h"`, or
  across the split with `--header-out` (`"../../include/lib/a.h"`). A quoted C header found
  beside a `.cnx` is named by a path back into the source tree (`"../../src/lib/dev.h"` with
  `-o out`). The cost: output is tied to where it was written relative to the sources, so a
  build that copies generated output elsewhere (a Docker context, a vendored `gen/`) and
  compiles it with `-I` flags that used to work now fails. Generate in place, or regenerate
  where it is built. Angle includes and includes found along the search path are unchanged.
- **`atomic` implies `mut`, and `atomic mut` is error E0919** (ADR-049, ADR-071, Issue #2233).
  An `atomic` binding is writable on its own, so `atomic u32 count <- 0;` is now written, not
  read-only, and generates `volatile uint32_t`, not `const volatile`. Every `atomic mut`
  declaration, until now the only way to write a working atomic, must drop `mut`. An `atomic`
  nothing writes is E0899 ("remove `atomic`"), and `atomic const` is E0898.
- **New errors for bitmap and bit access** (ADR-007, ADR-034): a compound operator on a bitmap
  field (`flags.Mode +<- 1`) is E0857 (#2159); a field of a bitmap array that names no whole
  element (`a.A` on `F[2]`) is E0921 (#2186); a constant bit index or range past the indexed
  value's width (`small[20]` on a `u8`, `p.Mode[3]` on a 3-bit field) is E0920 (#1808).
- **A bit of a bitmap field is a bit of the bitmap** (ADR-034, Issue #2251): `p.Mode[1]`, with
  `Mode` at bits 4-6, reads and writes bit 5 of `p`, on a variable and on a register member.
- **A `volatile` is never a compile-time value** (ADR-064, Issue #2254): a read-only volatile is
  read where it is used, never inlined as its initializer, and does not size an array (E0909).

- **The command is `cnx`** (Issue #2164). No other name is installed, so a script, Makefile or
  `package.json` runs `cnx`. `cnx --version` prints `cnx v<version>`, and `cnx --help` names
  `cnx` throughout. The config file names, the PlatformIO build script and the npm package name
  are cnx's too (#2165, #2174, #2181).
- **Config files are `cnx.config.json`, `.cnx.json` and `.cnxrc`** (Issue #2165): the first
  non-empty one in a directory is read, and no file under any other name is. `--pio-install`
  updates whichever config the project already has.
- **`.cnx` is the only cnx source extension** (Issue #2167). A file with any other extension is
  not cnx source, as an input or as an include.
- **PlatformIO's build script is `cnx_build.py`** (Issue #2174). `cnx --pio-install` writes
  `cnx_build.py`, which runs `cnx`, and adds `pre:cnx_build.py` to `extra_scripts`. A build without
  `cnx` on PATH now fails with `cnx not found on PATH: npm i -g <package>`, not a Python traceback.
  `cnx --pio-uninstall` removes the script and its entry. Both commands read
  `extra_scripts` as PlatformIO does: a one-line list split at `, `, a value on the key's line that
  continues on indented lines below it, and no commented-out line; uninstall keeps every other script.
  A `${section.option}` reference is expanded first, as PlatformIO does, to choose how the hook is
  added; one only the build machine can expand, such as `${sysenv.X}`, stops install with a request
  to add `pre:cnx_build.py` by hand.
- **Diagnostics name the language `cnx`** (Issue #2169). Errors, warnings, help lines, the
  "no source files found" result and the formatter's errors say `cnx`, as in
  `cnx has no 'sizeof'`, and a symbol-conflict listing labels the language `cnx`. Tooling that
  matches on message text must match `cnx`. The MISRA Rule 14.3 comment on a `forever` loop in
  generated C reads "for cnx `forever`".
- **A config is read from the project root, and never from a directory above it** (Issue #2261).
  The project root is the nearest directory, from the entry file up, that holds a config,
  `platformio.ini`, `.git` or `package.json`. It already decided the include directories and the
  `.cnx/` cache; a separate search for the config went on past the `.git` or `package.json`, so a
  run could take its settings from one directory and its root from another. A config above the
  nearest `.git`, `package.json` or `platformio.ini` no longer applies: a shared config above
  several PlatformIO projects, or a `~/.cnxrc`, must be copied into each project that needs it. An
  empty config file marks the root and means the default settings, and an unreadable one warns;
  both used to pass the search on to a config above. `--pio-install` no longer shadows an
  ancestor's config (#2235), since none applies.
- **The repository moved to [smeltworks/cnx](https://github.com/smeltworks/cnx)** (Issue #2180).
  Links and git remotes under the old repository name redirect; update a clone with
  `git remote set-url origin https://github.com/smeltworks/cnx.git`. The coverage report moved
  to [smeltworks.dev/cnx](https://smeltworks.dev/cnx/coverage/), and GitHub does not redirect
  Pages, so a link to the old report is broken. Sonar analysis moved to the `smeltworks_cnx` project in the
  `smeltworks` SonarCloud organization: SonarCloud reports on a pull request only for a repository its
  organization's GitHub binding owns. Earlier history stays in the previous SonarCloud project.
- **The npm package is `@smeltworks/cnx`** (Issue #2181). Install with
  `npm install -g @smeltworks/cnx`; the unscoped `cnx` name on npm is another author's package.
- **A `critical` block on host or esp32 is error E0916** (ADR-050, Issues #1147, #1789).
  Disabling interrupts does not shut out every other execution context there: host
  cannot disable them from user space, and esp32 has a second core. The IRQ wrappers'
  "assume CMSIS" arm is gone. C compiled for a compiler the wrappers have no arm for
  now stops at an `#error`, so host-side tests can no longer stub `__disable_irq`.
- **Target descriptions are schema version 2** (ADR-049): every description gives
  `interrupt_mask`, so an inline description needs `#pragma interrupt_mask true` or
  `false`.

### Fixed

- **A concatenation that fills its `string<N>` compiles under `-Werror`** (ADR-045, Issue
  #1902). Its first part was copied with `strncpy` and each later part appended with `strncat`.
  gcc rejected the generated C with `-Wstringop-truncation` when the first part was exactly
  `N` characters long (`names[1] <- "eight ch" + "";` into a `string<8>[2]` element). Every
  part is now copied in with `cnx_string_copy`, as every other string copy is, so an element, a
  scalar, a declaration or an argument built from a concatenation compiles cleanly, whichever
  part fills it.
- **Narrowing, sign change and an out-of-range literal are rejected at every position a value
  lands in** (ADR-024, Issue #1618). E0868 and E0869 were checked at a declaration and an
  assignment only. They now apply to a compound assignment (`a +<- wide`), a return value, an
  argument (also through a callback field), an array element (listed or filled), a struct field
  initializer and either arm of a ternary, and to a C function's result at each of them. Code
  that relied on the gap must say which bits it means: `wide[0, 32]`.
- **A literal operand that does not fit its target is rejected** (ADR-024, Issue #1618).
  `u8 a +<- 300` and `a <- a + 300` compiled to a saturating clamp; a value known at compile
  time that does not fit is now E0868, and ADR-044's clamp applies to runtime values only. A `|`/`^`
  operand must fit the target's width; `&` and a `/`/`%` divisor are exempt. A value the
  compiler folds, bound names included, is checked at the target's width: with
  `u32 BIG <- 0x10000`, `u32 y <- BIG * BIG` is E0910, the static-initializer overflow code,
  at every position.

- **An atomic read-modify-write compiles on host and esp32** (ADR-049, Issue #1789).
  It is a GNU `__atomic` compare-exchange loop, which esp32's GCC builds as inline
  `s32c1i` for 8-, 16- and 32-bit types. A wider type there needs libatomic, and the
  output's requirements say so.
- **A retry loop evaluates its value once** (Issue #1807). `w +<- f()` called `f()`
  again on every failed LDREX/STREX attempt.
- **`&x` is a compile error** (ADR-006, Issue #2117). `&` was never cnx syntax, but it was
  accepted and emitted as C's address-of: `u32 a <- &x;` became `uint32_t a = &x;`, which
  gcc's `-Werror=int-conversion` rejects. It is now unknown syntax. A C function's pointer
  parameter takes its `&` from the header (`bump(a)`), and a variadic out-parameter takes it
  from a scanf-family call's literal format (ADR-071 Decision 2): `global.sscanf("7", "%d", parsed)` is
  `sscanf("7", "%d", &parsed)`. A format that is not a string literal is E0930.
- **A bitmap field or an untagged C enum constant passed to a `mut` parameter is E0915**
  (ADR-006, Issues #2124, #2396). `bumpBool(f.a)` emitted `bumpBool(&((f >> 0) & 1))`, and a
  `typedef enum { C_MODE_A }` or `enum { ANON_LIMIT }` constant emitted `&C_MODE_A`, which gcc
  rejects. A scanf-family conversion's argument gets the same check.
- **An `atomic`, `volatile` or register-member scanf-family target is E0915** (ADR-071,
  Issue #2398). `global.sscanf("3", "%u", reading)` with a `volatile` `reading` emitted
  `sscanf("3", "%u", &reading)`, and the write through `...` dropped the qualifier silently.

## [0.4.0] - 2026-10-17

v0.4.0, not v0.3.2: ADR-071 makes an existing program fail to compile wherever it
writes a variable without declaring it `mut`, so every project needs edits (owner
ruling on #1933, 2026-10-17).

### Added

- **`mut` (ADR-071, Issues #2099, #2103).** A binding that is written is declared
  `mut`: `mut u32 counter <- 0;`, `void bump(mut u32 v)`, `for (mut u32 i <- 0; ...)`.
  It applies to parameters, locals, `for` variables, globals and scope members. A
  read-only binding is generated with C's `const`, and a parameter's C signature now
  follows its declaration, not what its body happens to do.

- **Twelve length properties (ADR-058, Issue #1975).** A length now says which kind it
  is: the **value** (what it holds now), the **type** (its declared width) or the
  **memory** (C's `sizeof`, answered by the C compiler). Each comes in bits, bytes,
  characters and elements, e.g. `n.value_bit_length`, `s.value_char_count`,
  `Cfg.type_byte_length`, `Cfg.memory_byte_length`, `s.memory_char_count`. Also fixes
  #1867, #2076 and #2078.

- **A struct field can carry its own `clamp`/`wrap` modifier** (ADR-044, Issues #1411,
  #1887): `struct Reading { u8 level; wrap u8 checksum; }`. The default is `clamp`, and
  an array element takes its array's modifier.

- **A case label may be written `this.X` or `global.X`**, including a member chain such
  as `this.State.IDLE` (ADR-016, Issues #1629, #2075).

### Changed

- **Every binding is read-only unless declared `mut`** (ADR-071, Issue #2103). This is
  a **breaking change** for every existing project: a write to a binding not declared
  `mut` is new error **E0900**. That covers an assignment to it or through it, a
  `safe_div`/`safe_mod` output, and passing it to a `mut` parameter or to a C/C++
  pointer or array parameter that is not `const`. 2284 of the corpus's 8477 bindings
  needed `mut`. The migration is to add `mut` to each binding E0900 names.
  - `const` on a declaration is now error **E0898**, since every binding is already
    read-only. Remove it. (534 bindings in the corpus declared it.)
  - A `mut` binding nothing writes is error **E0899**. A parameter of a callback-type
    function, a global and a public scope member are exempt.
  - E0877 (assignment to a const) and E0878 (const passed to a non-const parameter)
    are retired into E0900.

- **cnx has no `sizeof`** (ADR-058, ADR-023 stays Rejected, Issue #1975). This is a
  **breaking change**: `sizeof(...)` is error **E0603**, and `.bit_length`,
  `.byte_length`, `.char_count` and `.element_count` are removed (**E0886**, whose help
  names the replacement). E0601 and E0602 are retired.

- **An `if`, `else`, `while` or `for` body must be a braced block** (MISRA C:2012
  Rule 15.6, Issues #1090, #1795). This is a **breaking change**: an unbraced body is
  error **E0716**. `else if` is the one unbraced `else` allowed. The migration is to
  wrap each body in `{ }`.

- **A struct declared without an initializer gets its default, not `{0}`** (ADR-029,
  ADR-017, Issues #1283, #1565, #1570, #1970, #1971). A callback field is never null:
  every declaration site, and `<Struct>_init()`, use one recursive default. Before
  this, calling the callback of such a struct crashed (exit 139).

- **A parameter that shadows a file-scope name is emitted as `<function>__<name>`**
  (ADR-057, Issue #1290), as a local already was. `global.total` inside
  `paramCase(u32 total)` returned the parameter.

- **A variable is defined once its declaration closes** (ADR-030, Issue #1643), so
  `u32 k <- k + 1` is E0427 `'k' is not defined`, and so is a global or scope member
  used above its declaration. Both used to compile, the first reading an uninitialized
  value.

- **`ITranspilerConfig.outDir` is required** (Issue #2086), for anyone calling the
  library. `outDir: ""` and `headerOutDir: ""` mean the current working directory, and
  a missing `headerOutDir` falls back to `outDir` (#2104). A files-mode run with
  `outDir: ""` used to write the `.h` and silently skip the `.c`. Directories are
  created only when something is written into them.

- **Only a lowercase `.cnx` is cnx source** (Issue #1833). A
  source spelled `Colors.CNX` (or any other case) is now **E0518** at the
  include that names it, or for the run's input, and nothing is written. It
  used to be transpiled with its generated header named `Colors.CNX`, so an
  in-place build overwrote the source and exited 0.

### Fixed

- **A string value lands in no scalar** (ADR-024, Issue #1739). `u32 g <- "hello";`,
  `take("arg")` and `return "r";` into a non-string target are error **E0914**. A
  private scope const is inlined as its settled value, not re-read from its source
  text: `return M;` with `const u32 M <- N * 2;` emitted `N*2`, which C bound to the
  file-scope `N`.

- **Case labels are checked and bound once** (ADR-016, Issues #1629, #2072, #2075,
  #2108). `case NOPE` emitted an undeclared C name at exit 0, and is now E0427. A label
  that is not a constant (a variable, a function, a struct or bitmap field, a string
  const) is new error **E0717**. `case this.X` outside a scope is E0431, and
  `case global.HDR_K` for a header macro is emitted `case HDR_K:`.

- **A parenthesized comparison is a comparison** (Issue #1195):
  `if ((n < 5) && (n > 1))` no longer fails E0701.

- **E0800/E0802 see a `this.`, `global.` or `Scope.`-qualified zero const** (ADR-051,
  Issue #1268). `n / this.ZERO` emitted `n / 0` at exit 0.

- **Compound assignment to a struct field or array element clamps** (ADR-044, Issues
  #1411, #1887). `p.x <- p.x + 10` on a `u8` at 250 wrapped to 4. An index with a side
  effect is evaluated once.

- **No shell parses a compiler name** (Issue #1827). A compiler named in
  `compile_commands.json` or `CNX_CROSS_COMPILER`, such as `gcc;touch x;`, ran
  arbitrary commands through `/bin/sh`. Every toolchain process now starts from an
  argument array.

- **The library's `parseWithSymbols` settles symbols the way the CLI does** (Issue
  #2036): a const-sized array (`u8[N] buffer`) reported dimension `0`.

- **A shadowing local's name and its `.char_count` cache agree** (Issues #1946, #1650,
  #1953), and a block's rename ends with the block.

- **Compound division and modulo by a compile-time zero are errors** (ADR-051,
  Issues #1770, #1796). `x /<- 0` is E0800 and `x %<- ZERO` is E0802, as
  `x / 0` and `x % ZERO` already were, in a statement and in a `for` header
  alike. Both were accepted and emitted `x /= 0U` or `x %= 0U`.

## [0.3.1] - 2026-10-07

### Added

- **`--no-cpp`** asks for C, as `cppRequired: false` does (Issue #1844).

- **Targets (ADR-049, Issue #1668).** A program names exactly one target: `#pragma target <name>`, `--target <name>`, `"target"` in `cnx.config.json`, or the board of the PlatformIO environment being built. `targets/targets.cnx` is the catalog (`cnx --help` lists it). A platform it does not name can be described inline, one `#pragma` per field (E0512–E0514). The run prints `Target: <name> (<source>)`.
- Return values of non-void functions must now be used or explicitly discarded with `(void) f(...)` — new error **E0708** (ADR-070, Issue #847). This is a **breaking change**: 61 call sites across the test suite and examples were migrated.

### Removed

- **`--no-preprocess` and the `preprocess` config key** (Issue #1844). A header's
  language is judged on its preprocessed text, so a run that includes C/C++
  headers needs a C preprocessor (E0516 when there is none), and a header that
  cannot be preprocessed -- alone, after the headers before it, or in the #985
  translation unit -- is E0517 at the include that reached it, with the
  preprocessor's message as help. No header's language is judged on its raw text any more.

### Changed

- **`cppRequired: false` now means C only** (Issues #1319, #1844). This is a
  **breaking change** for a project that wrote it out: v0.3.0 read `false` the same as
  leaving the key out, and switched to C++ when a header was C++. Now a run that asks
  for C (`cppRequired: false`, `--no-cpp`) and reaches a C++ header fails with new error
  **E0507**, reported at every `.cnx` `#include` through which the run meets C++. The
  migration is to remove the key, or set it to `true`. A run that does not say is still
  C++ when a header it reaches is C++, and `cppRequired: true` (`--cpp`) still forces C++.
  1.1 now judges each header once, on its preprocessed text, so a run that passed cold
  no longer fails warm (#1851).

- **An implicit float-to-integer conversion is error E0891** (ADR-024, Issue #1800).
  This is a **breaking change**. `u32 b <- k;` with `f32 k`, a floating composite
  or ternary, a call returning a float, and the same in an assignment, a `for`
  header, an argument, a return, a struct field or an array element were
  accepted. They were emitted as C's own conversion, which is undefined for NaN
  and for a value past the target's range. The migration is the explicit cast,
  `(u32)k`, which truncates and then clamps to the range (ADR-056).

- **A PlatformIO project's `default_envs` includes the build machine's
  `PLATFORMIO_DEFAULT_ENVS`**, as PlatformIO appends it (ADR-049, Issue #1794).
  A standalone `cnx` run read the file alone, so it could report a target for
  fewer environments than `pio run` builds.

- **A program that names no target is error E0515** (ADR-049, Issue #1668). This is a
  **breaking change** for every existing project. The migration is one line:
  `"target": "<name>"` in `cnx.config.json` covers every file. `#pragma target <name>`
  in the entry file or `--target <name>` also work, and an unknown name is E0510.

  A PlatformIO project whose boards map to known targets needs no line, but should
  **re-run `cnx --pio-install`**. The regenerated `cnx_build.py` passes each build's
  environment (`--pio-env`) and shows the target and any warnings in `pio run`. A script
  written before this passes no environment. A project whose environments name different
  targets, and that sets no `default_envs`, then fails every build with E0511.

- **Mixed integer and floating arithmetic is error E0810** (ADR-024, MISRA C:2012
  Rule 10.4, Issue #1668). This is a **breaking change**. `u32 i <- 3; f32 x <- i * 2.5;`
  used to evaluate to 6.0, because the integer operand chose integer arithmetic. Write
  the conversion where it happens: `(f32)i * 2.5`. The rule covers compound assignment,
  comparisons and a conditional's value arms. Its categories are MISRA's: signed,
  unsigned, floating, Boolean and character, and each named enum is its own.

- A generated `#include` now names its target **relative to the header output
  directory**, so that directory alone is sufficient on the C compiler's search
  path (Issue #1467). Previously the transpiler swapped the extension on whatever
  you typed, so a bare `#include <utils.cnx>` resolving to a subdirectory emitted
  `#include <utils.h>` while the header was written to `<headerOut>/Display/utils.h`
  — the transpiler exited 0 and the generated C did not compile.

  This is a **breaking change**, and like E0507 above it breaks projects that did
  not change: a build that passes `-I include/Display` today, to reach a header the
  transpiler named without its prefix, needs `-I include` after this. The migration
  is one line of build configuration — point the include path at the header output
  directory and remove the per-subdirectory entries it needed to compensate.

- **Removed `--base-path`** and the corresponding `basePath` key in
  `cnx.config.json` (Issue #1467). It stripped a leading prefix from header
  output paths, for a time when the whole project directory was the input; once
  the entry point became a single file, the prefix it removed no longer appeared,
  and passing it became a no-op for the case it was written for. Its only
  remaining effect was to move a header without moving the `#include` naming it,
  producing output no `-I` could reconcile.

  `--base-path` now exits 1 with `Unknown arguments`. A `basePath` key left in
  `cnx.config.json` is currently discarded **silently** — unknown config keys
  produce no diagnostic (Issue #1490) — so remove it by hand.

- MISRA C:2012 Rule 17.7 is now **enforced** rather than baselined. Calls the transpiler emits while lowering string operations carry an automatic `(void)` cast; author-written discards are a compile error.
- Stdlib function metadata moved to `StdlibFunctions`, shared by `FunctionCallAnalyzer` and `ReturnValueUseAnalyzer`.

### Fixed

- **A struct initializer on a type that is not a struct is error E0358** (ADR-014,
  Issue #1802). `u32 x <- { a: 1 }` and `Flags f <- { A: 1 }` were accepted
  and emitted a designated initializer that C rejects. That held whether they
  stood alone, as a struct's field, or as an array's element. A bitmap takes
  its backing integer, standalone or as a struct's field (`Flags f <- 3`,
  `Cfg c <- { word: 1, f: 3 }`), then its fields one by one (ADR-034).

- `StdlibFunctions.header()` no longer resolves inherited `Object` members, so a callee named `constructor` or `toString` is no longer treated as a known stdlib function.
- E0708 now covers a bare intra-scope call (ADR-057 house style), scope methods reached through a `.cnx` include, and non-void functions declared in an included `.hpp` — each was silently exempt through a name-resolution gap.
- A cast to a type other than `void` no longer silences E0708; only `(void)` is an explicit discard.
- Transitive const inference now sees through a cast, so an explicit `(void)` discard no longer hides a mutating callee and infers the caller's parameter as `const` (Issue #1259). MISRA C:2012 Rule 11.8 is enforced as a result.

## [0.3.0] - 2026-08-24

> Minor rather than patch because generated C symbol names changed: scope members now
> transpile with a `__` separator (`LED_on()` becomes `LED__on()`). No `.cnx` source
> changes are required; C/C++ that calls generated names does need updating.

### Added

- Toolchain requirements are now a per-feature registry, and `docs/compatibility.md` is generated
  from it, so what the output costs the user is recorded where it is emitted (Issue #1143)
- E0806: compound assignment on a `bool` is rejected — only `<-` is valid; flip a flag with
  `flag <- !flag` (MISRA C:2012 Rule 10.1, Issue #1145)
- E0807: arithmetic, bitwise, shift and relational operators are rejected on a `bool` operand,
  including bool-valued expressions — a comparison, a logical result, a bool-returning call, or a
  ternary with bool arms (MISRA C:2012 Rule 10.1, Issue #1183)
- E0201: source identifiers containing `__` are rejected, reserving it as the qualified-name
  separator (ADR-063, Issue #1117)

### Changed

- **BREAKING** — generated C symbol names for scope members use `__` instead of `_`
  (`LED_on()` → `LED__on()`). `Scope_member` was not injective: a global `Reg_flags` and a
  scope member `Reg.flags` both emitted `Reg_flags`, and two different scopes could collide on
  one identifier. Both transpiled with exit 0 and failed in the C compiler (ADR-063, Issue #1117)
- **BREAKING** — `bool` no longer participates in arithmetic. `flag +<- true` and
  `n / (a && b)` were accepted and are now rejected; the latter compiled to a runtime
  division by zero (Issues #1145, #1183)
- `clamp` now governs arithmetic expressions, not only compound assignment (Issue #1152)
- The `cnx_` prefix is reserved, and include identity is keyed on path rather than basename
- Regression fixtures moved from `bugs/` into `tests/bugs/`, so every fixture-walking script
  covers them (Issue #1142)
- - ADR numbering now follows an explicit release-band rule: an ADR's band is the release it must
    ship in, and cutting `v(N+1)` requires every non-terminal ADR in band `N` to be implemented.
    The rule is documented in [`docs/decisions/README.md`](docs/decisions/README.md) and CLAUDE.md.
- Seven ADRs that were mis-filed in the `1xx` band were renumbered into `0xx`, since they are
  v1-gating work: ADR-108 → ADR-064, ADR-109 → ADR-065, ADR-110 → ADR-066, ADR-112 → ADR-067,
  ADR-113 → ADR-068, ADR-114 → ADR-069, ADR-115 → ADR-070. Older entries in this changelog and
  all cross-references were updated to the new numbers; the old→new mapping table lives in
  `docs/decisions/README.md`, because existing GitHub issues and merged PRs still cite the old
  numbers. The `1xx` band now holds only the v2 roadmap (ADR-100–106, ADR-111), which is what it
  was created for.
- ADR-065 (CodeGenerator Decomposition) status corrected from `Research` to `WIP` — its
  classifier + handler + utils pattern shipped in PR #447, but the decomposition it prescribes
  is not finished.

### Fixed

- Scope member visibility is carried across `#include`, so a private member is no longer
  silently dropped from a consuming file (Issue #1190)
- Array dimensions resolve through one shared evaluator: an arithmetic dimension
  (`u8[8+1]`) no longer loses its array-ness, a multi-dimensional struct field (`u8[2][3]`)
  keeps every dimension, and a hex-sized array (`u8[0x10]`) keeps its bounds checking
  (Issues #1127, #1157, #1158, #1159)
- Cross-file struct parameters resolve by canonical identity: the header keeps auto-`const`
  and the call site passes an address (Issue #1139)
- Bare scope-local type names are qualified in generated C output (ADR-057, Issue #1130)
- Over-indexing a scalar or array base is rejected instead of silently emitting wrong C (Issue #1106)
- Duplicate system `#include` directives are removed (Issue #1108)
- A multi-line `lib_extra_dirs` in `platformio.ini` keeps every path, not just the first
  (Issue #1181)
- `TypedefParamParser` no longer strips the last word of an unnamed multi-word type, so
  `void (*)(unsigned int)` keeps `unsigned int` rather than becoming `unsigned` (Issue #1189)
